# Agent Note: 内嵌 code-server 编辑器插件（@amadeus-dsh/editor）

Status: implemented

## 问题

Agent 修改工作区文件后，用户需要在同一个界面查看和编辑文件，同时保留项目配置、编辑器扩展和未保存的草稿。原 `Amadeus` 由容器入口启动 code-server，通过修改压缩后的 `workbench.js` 注入 `amadeus.reloadFile`，并生成合成的 `.code-workspace` 文件传递桥接标识；这些做法把编辑器与宿主启动器、外部程序版本和工作区配置绑在一起。

[与 DSH 解耦的决策](../architecture/2026-10-25-dsh-decoupling.md) 要求插件独立分发、仅使用公开扩展点，并将外部程序的安装交给部署环境。编辑器需要在这些约束下完成工作区打开、文件定位和关闭保护。

## 决策

[`@amadeus-dsh/editor`](../../../../packages/editor/README.md) 是独立 bundle。它通过 DSH 的右侧栏、文件操作插槽和快捷键提供 code-server 页面，不声明文件地址匹配规则，因此文件树和对话引用的普通单击仍使用宿主原生预览。

### 运行方式与持久化

插件支持受管进程和外部 `upstream`。受管模式检测用户安装的 code-server，使用独立数据目录启动回环服务；外部模式使用已运行的免认证 HTTP 或 HTTPS 服务，不负责启停该实例。两种模式的配置、版本要求和部署前提由[包 README](../../../../packages/editor/README.md)维护。

[`process.ts`](../../../../packages/editor/src/process.ts) 用带随机所有者标识的 `owner.lock` 排他占用数据目录，拒绝同时使用同一目录的存活所有者，并在回收失效锁时清理已退出进程的桥接注册。用户设置和第三方扩展分别保存在 `user-data/` 与 `extensions/`；初始设置仅在文件不存在时创建。桥接扩展通过同目录的临时副本和重命名替换，不覆盖其他扩展。

数据目录不依赖当前工作目录，避免在用户项目里生成编辑器运行数据。外部程序缺失或启动失败只停用编辑器功能，工作区接口返回不可用原因，插件设置仍可访问；配置与必要宿主服务缺失则按插件加载错误处理。

### Desktop 直连与 Web 代理

Web 页面经同源 `/amadeus/code` 代理加载；Desktop 使用工作区接口返回的独立 code-server HTTP 或 HTTPS 来源。Desktop 的 `dsh-app://app` 不是 code-server 的普通网页运行环境，而同一 DSH 端口上的 HTTP iframe 又受宿主 WebSocket 转发规则影响，因此 Desktop 不复用该代理作为 iframe 地址。

[`proxy.ts`](../../../../packages/editor/src/proxy.ts) 剥离宿主 Cookie、Authorization 和逐跳头，重写重定向地址，并持有活动 HTTP 与 WebSocket 连接。核心工作台的升级路径从返回的 HTML 中发现，通过公开的精确路径注册接口登记；插件不修改 WebServer 的私有路由表。

[`index.ts`](../../../../packages/editor/src/index.ts) 的工作区和桥接接口校验公开来源的 Host、显式来源信息及规范化后的工作区路径。状态修改还需要工作区接口签发的随机 capability。Desktop 转发会移除 Origin 和 Sec-Fetch-Site，因此两者均缺失时依靠 Host 与 capability 校验；显式跨站来源仍被拒绝，不额外放开 CORS。

代理和直连均不能代替访问认证。code-server 具备终端、任务和扩展执行能力；入口的 realpath 校验防止文件定位越界，但不提供操作系统级隔离。部署以可信的宿主用户、回环网络或受保护的外部网关为前提，外部实例还需要与 DSH 共享相同的工作区路径。

### 原生工作区与公开桥接

编辑器直接使用 `?folder=<工作区目录>`，保留 `.vscode/settings.json`、任务和扩展推荐的原生作用域。会话目录来自宿主工作目录服务；持久化但未加载的会话从公开持久化服务读取目录信息。文件定位同时校验工作区真实路径，并处理 Windows 盘符和资源地址。

随包分发的 [`amadeus-bridge`](../../../../packages/editor/extension/extension.cjs) 只调用公开 `vscode.*` API 和内置命令，不修改 code-server 或第三方扩展。每个工作区窗口以独立 UUID、随机 Bearer token 和回环端口注册到私有 `bridges/` 目录，文件名包含规范化目录的散列；多个窗口不会覆盖同一注册文件。

[`WorkspaceBridges`](../../../../packages/editor/src/bridge-workspace.ts) 校验匹配的注册记录。文件打开和主题请求并发发给该目录的注册实例，任一成功即可；关闭保护查询所有实例，任一未知或失败均阻止破坏性操作，不将断连当成干净状态。

文件定位通过 `openTextDocument` 和 `showTextDocument` 打开文本并定位行列，非文本文件使用 `vscode.open`。磁盘外部修改依赖编辑器原生监听，未保存文件的冲突由编辑器处理。主题同步写入用户级设置，保留项目设置的优先级；代码和终端字号由 code-server 自己管理。

### iframe 保留与关闭保护

[`FramePool`](../../../../packages/editor/src/frame-pool.ts) 按规范化工作区目录保留有上限的 iframe。iframe 位于插件拥有的独立 DOM 容器中，标签页占位只负责定位和可见性，避免会话切换或标签页组件重新挂载导致编辑器重载。每次可见挂载有独立所有者；后台回调和旧挂载的清理不能隐藏其他可见所有者的 iframe。

DSH 的关闭处理器同步提交标签页关闭，无法等待异步检查。因此 [`CloseCoordinator`](../../../../packages/editor/src/client-close.ts) 保留 iframe，异步查询草稿状态，在需要确认或状态未知时重开标签页。关闭标签页不等于立刻销毁编辑器；LRU 驱逐另行执行相同保护。

保存操作覆盖有修改的实例，随后重新查询全部实例，只有确认干净才完成关闭或驱逐。丢弃只允许单实例，并在执行公开的撤销关闭命令后复查实例身份和草稿状态。未命名文档、自定义编辑器和 Notebook 的脏标签页均纳入检查；保存失败、状态未知和用户取消时保留 iframe。多窗口场景的保守检查可能要求关闭干净窗口的用户也处理其他窗口的草稿。

### 所有权与清理

服务端根 effect 持有路由、桥接请求、代理和受管进程，按撤销路由、断开代理、取消并等待桥接请求、停止受管进程的顺序释放；后续资源的释放不因前一步失败而被跳过。外部模式不终止上游服务。客户端卸载会取消请求、定时器、动画测量和确认框，并移除自身 iframe 与注册，不保存用户草稿。

## 考虑过的替代方案

**继续生成合成的 `.code-workspace` 文件。** 它能携带桥接标识，但改变单根项目配置的作用域，并要求额外维护工作区文件的恢复逻辑。环境变量传递注册目录、扩展按真实目录独立注册后，不再需要包装用户工作区。

**继续给 `workbench.js` 打补丁。** 压缩变量名和构建产物随版本改变，私有命令注入增加升级成本。公开扩展可完成文件打开、主题设置和关闭保护，原生文件监听负责磁盘刷新，因此这些能力不以源码补丁为前提；PDF 划词等未接入能力保持延期。

**完全不安装桥接扩展。** 仅用目录参数可以浏览和编辑文件，却不能在保留 iframe 的同时定位文件或检查草稿。显式的 `bridgeMode: disabled` 保留这种部署选择，但不会自动从完整模式降级。

**只支持外部常驻服务。** 这能减少进程托管代码，却要求单机用户额外管理服务生命周期、用户目录和扩展目录。受管模式统一这些运行参数，外部模式继续满足独立部署；两者都不替用户安装外部程序。

**把字号与主题一起同步。** 用户需要独立调整编辑器和终端字号，同步字号会覆盖编辑器里的用户设置。桥接只同步主题，字体配置不由 DSH 控制。

## 后果

编辑器以独立预构建 bundle 安装，沿用项目工作区配置、编辑器扩展和用户设置。代价是本机或部署环境需要准备 code-server；默认共享数据目录只能有一个受管所有者，Web 与 Desktop 同时运行时需要分配不同数据目录或显式配置外部实例。

工作区热缓存降低重载成本，但占用文件监听和扩展宿主资源；缓存上限与初始监听排除项限制其规模。缺失或陈旧桥接会阻止关闭保护，注册损坏会报错；使用方需要处理服务连接而不能依赖静默降级。

Desktop 的宿主快捷键优先级仍由宿主管理，插件不提供 iframe 独占键盘。编辑器内置终端可以通过菜单打开；宿主升级、窗口内浮动面板和第三方扩展行为需要实机验收，不能仅由布局数据断言推导全部视觉结果。

核心工作台连接使用精确 WebSocket 路径。第三方扩展和端口转发需要的任意升级子路径不在支持保证内；编辑器选区引用与 PDF 划词桥接尚未接入。这些缺口不通过修改 DSH、code-server 或 LaTeX Workshop 解决。

[`tests/`](../../../../packages/editor/tests/) 覆盖真实 Loader 组合、配置与路径校验、代理连接销毁、桥接认证与多实例关闭保护，以及 iframe 折叠、位移、所有者交接和主题就绪状态。加载测试读取构建产物；单元测试中的 DOM 几何不等同于真实 Desktop 渲染验收。
