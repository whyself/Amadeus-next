# 清理推理过程泄漏

推理过程泄漏指视角停留在写作会话而不在仓库的文字：它引用只有那次会话才看得见的东西，叙述改动而不是现状，或者在和已经离开的评审者争论。只要段落带有事实性子句，修法就不能只是删除：要把每个事实改写成在 HEAD 上独立成立的句子，再删掉周围的转录；不带任何事实性子句的段落（审计编号、控制流叙述）直接删除。**必备背景：** [amadeus-prose-standard](../amadeus-prose-standard/SKILL.md) 拥有本 skill 所依赖的完整命题规则。它是指导，不是脚本。

## 唯一的检验

对每段可疑文字都问：**一个只看 HEAD、看不到任何会话记录、PR 讨论或未提交草稿的读者，能否解析每个引用、验证每个断言？** 不能，就从仓库的视角重述保留下来的事实，删掉其余部分。能，就不算泄漏，不管它听起来多像历史。但可解析只是通过了本 skill 的标准：在描述现状的文档（README、docs、JSDoc）里，可解析的变更故事仍然是变更叙述，按第 3 类移到它该在的地方。

## 分类

1. **失效的设计会话引用**：`(决策 7)`、`(审计 C2)`、`设计 §4.7`、`计划 §1.4`、阶段代号（`T4`、`W3`、`P-I`）、"设计台账"、"(B 方案)"。决策有已提交的归属时，按名称和路径引用；没有时删掉引用，把它的事实子句改写成独立的句子。
2. **stack 或 PR 视角**："后续 PR"、"本 PR 新增"、"上一个提交"。写已发布的机制或扩展点；推迟的工作改成 `TODO` 标记或 issue 引用。
3. **变更叙述和版本戳**："以前"、"不再"、"旧的 X"，以及指示性的时间戳（"v1"、"这次"、"目前"、与过去状态对比的"现在"）。写现在的行为；修复过的回归写成现在时的反事实（"没有 X 时会发生 Y"），不写成仓库历史（"以前会 Y"）。
4. **评审过程**："评审中否决："、"评审者确认了"、草稿序号（"本文第 5 版"）、轮次归属。把保留下来的决定和理由写成平实的事实；删掉谁在什么时候说的。
5. **对评审者的辩护**："这个类型断言是安全的，它只是……"、"这样写是对的，因为……"。一段论证自身正确性的注释是在回应评审者，不是在帮助维护者。写出让代码安全的不变量；如果代码已经表明了这一点，就删掉注释。
6. **复述和推导过程**：控制流叙述（"先 X，再 Y"）、测试讲解、对显然分支的论证。删除；只保留非显然的契约或不变量。
7. **含糊和计划残留**："暂时应该没问题"、"应该够用了"、没有标记的推迟。改成 `TODO`/`FIXME`，或写出实际的上限；删掉含糊的说法。
8. **写作语言混杂**：在以某种语言书写的文字中夹带另一种语言的工作片段，例如中文文档里夹着未翻译的英文短语，或英文代码注释里夹着 "端"、"设计稿"、`---- 私有 ----` 这类分隔符。翻译或删除。标识符、命令和专有名词不算混杂。

## 不算泄漏的内容

不加约束地清理引用，两个方向都会出错：删掉长期有效的引用，留下已失效的引用。按原文执行下面的保留规则，[例子](references/examples.md) 为每一条提供校准：

- **issue 引用**：`#1470`、`TODO(name):`、"issue #N 负责后续工作" 在 HEAD 上都能解析，任何文字里都保留，包括 README。
- **提交信息里的 PR 和 issue 引用**：提交信息本来就是记录改动经过的地方。
- **抑制规则的理由**：`oxlint-disable … -- 理由`、覆盖率忽略的理由、空 catch 的说明都是必须写的文字；理由错了就改正，绝不删除。
- **现在时的反事实回归说明**："没有 X 时会发生 Y"、"简单地 X 会……"。
- **实测的上限**："(实测：512 层嵌套约 0.15 秒)" 用来校准一个常量；"实测" 这个证据词是承重的。
- **运行时的新旧状态**："旧连接排空后新连接才开始接受请求" 描述的是运行时生命周期，不是变更历史。
- **在仓库外解析的外部引用**：标准的章节（RFC 9110 §10.1.5）、设计稿中的画板名称；§ 的禁令针对的是未提交的内部草稿，不针对外部标准或拥有自身章节编号的已提交文档。
- **项目口吻和固定体裁**：作为项目口吻的 "我们"。

## 工作流程

1. 范围和排除按 [amadeus-prose-standard](../amadeus-prose-standard/SKILL.md) 执行：要求明确的范围；不碰 `node_modules/`、`lib/` 等依赖和构建产物。
2. 先只读审计：运行 [召回探针](references/recall-batteries.md)（带 `--hidden`，以便搜索 `.agents/`），信任每个探针的结果之前，先用一个已知的阳性例子和一个相近的阴性例子校准它，然后从语义上判断每一条命中。探针只是探测手段，不是定义；还要在不带模式的情况下通读范围内文字最密集的部分（模块 JSDoc、README、docs）。
3. 模型或用户可见的文字按 [amadeus-prose-standard](../amadeus-prose-standard/SKILL.md) 处理，只有在有对应的行为验证时才修改，否则保持原文不变并报告推迟。
4. 删除任何内容之前，先列出段落里的命题（见 prose-standard），并对照 [过度修正陷阱](references/examples.md#过度修正陷阱) 检查：精简是否把一项义务变成了认可、把假设提升成了已发布的功能、删掉了一个真实的事实，或丢掉了证据来源。
5. 验证：重新运行探针，预期只剩下允许保留的内容和本 skill 自身目录中的引用；确认剩下的每个引用都能在 HEAD 上解析；运行改动涉及的检查。
