# 泄漏的少样本例子

用这些例子识别适用的原则，不要当作套用的模板。本文件为了校准有意引用泄漏的措辞；[召回探针](recall-batteries.md) 排除了本 skill 的目录，这里的措辞不代表别处可以这样写。

## 失效的引用

### 有已提交归属的决策序号

**泄漏：** "斜杠输入按可见目录解析（决策 21）。"

**修正：** "斜杠输入按可见目录解析，这是纯文本引用的决策，由输入处理文档 `docs/input.md` 拥有。"（示例路径）

序号在 HEAD 上解析不到任何东西；决策的名称和拥有它的文档路径可以。每个文件里至少写一次归属文档的路径（文字支持时写成链接），之后可以只用可搜索的名称。

### 没有归属的决策序号

**泄漏：** "注册表拒绝重名（决策 7：名称是扁平的，没有命名空间）。"

**修正：** "注册表拒绝重名；名称是扁平的，没有命名空间。"

没有任何已提交的文件拥有 "决策 7"，所以删掉引用，但它的事实子句（名称是扁平的）被改写成独立的句子，而不是一起删掉。

### 审计条目编号

**泄漏：** "渲染是纯函数：相同的快照得到相同的字符串（审计 R3）。"

**修正：** "渲染是纯函数：相同的快照得到相同的字符串。"

仓库里没有审计文档；这个编号是纯粹的会话速记，不带任何命题。

### 未提交草稿的章节号

**泄漏：** "分层遵循设计（v2 §3.2）：`src/core/` 是纯核心。"

**修正：** "分层：`src/core/` 是纯核心。"

没人提交过的草稿的 `§N` 无法解析。对比："按 RFC 9110 §10.1.5 转义" 保留，外部标准按设计就在仓库外解析，拥有自身章节编号的已提交文档也可以按章节引用。

### 计划阶段代号

**泄漏：** "`src/client/` 是外壳（T4）；适配器归 P-I 迁移负责。"

**修正：** "`src/client/` 是外壳；适配器在 `src/client/adapters/` 中。"

阶段代号索引的是一个从未落地的计划。用这个阶段产出的东西替换代号。

## stack 和 PR 视角

### 长期文字里的 stack 位置

**泄漏：** "将来的远程后端会实现这个接口（沙箱后端在这个 stack 的后续 PR 里）。"

**修正：** "远程后端可以实现这个接口，而不需要修改渲染层。"

长期存在的文字看不到 stack。保留扩展点的契约；待做的工作放在 PR 本身、`TODO` 或 issue 里。

### README 里的 "本 PR"

**泄漏：** "本 PR 为会话列表加入了基于游标的分页。"

**修正：** "会话列表按游标分页。"

README 比任何一个 PR 都活得久；把机制写成当前的事实。

## 变更叙述和版本戳

### 带 PR 编号的事故经过

**泄漏：** "颜色以前来自 `--widget-*` token，但没有地方定义它们，所以总是渲染回退值；别名 token 修好了这个问题（PR #88）。"

**修正：** "颜色来自别名 token；未定义的 token 会渲染回退值。"

两个仍然成立的事实（当前机制和持续存在的失败行为）都用现在时保留了下来。这个 bug 的经过归 PR 和提交信息。

### 删除叙述

**泄漏：** "`probe` 字段随着这次删除去掉了；徽标现在走通用的投影对。"

**修正：** "徽标使用通用的投影对。"

从没见过 `probe` 的读者无法从它的消失中学到任何东西。与已删除的过去相对比的 "现在" 是一个版本戳。

### 修复过的回归 → 现在时的反事实

**泄漏：** "这里以前会把多字节标签重复编码。"

**修正：** "没有字节长度检查时，多字节标签会被重复编码。"

回归说明以现在时反事实的形式保留下来，并点出了那个检查；"以前" 则把它钉在了仓库考古上。

### 指示性的版本戳

**泄漏：** "这一版批量渲染是同步的；异步路径在路线图上。"

**修正：** "批量渲染是同步的。"（推迟的工作放在调用处的 `TODO(widget-batch):` 里。）

"这一版"、"v1"、"目前" 一合并就过期了。

## 评审过程

### 评审结论写进正文

**泄漏：** "评审中否决：缓存解析后的 spec。我们保持每次调用都解析。"

**修正：** "每次调用都重新解析 spec：spec 依赖调用时的 cwd，按请求做键的缓存会返回过期的根目录。"

保留决定和理由；评审者和轮次不是理由的一部分。

### 草稿序号

**泄漏：** "从本文第 5 版起，加载器也会校验清单。"

**修正：** "加载器会校验清单。"

文字描述的是已发布的现实；它自己的修订历史在 git 里。

## 对评审者的辩护

### 为类型断言辩护

**泄漏：** "这个断言是安全的，SDK 构造了这个对象，只是没把可选字段声明得足够严格。"

**修正：** "SDK 构造这个对象时会填充每个可选字段；声明的类型比运行时保证更宽松。"

写出维护者不能破坏的不变量。"只是……" 是在回应一个 HEAD 上没人提出过的质疑。如果不变量在代码中可见，就删掉注释。

### 诉诸评审权威

**泄漏：** "这样是对的，因为评审者确认过包装顺序。"

**修正：**（删除；包装顺序写在函数的 `@returns` 里。）

正确性的依据是不变量或测试，不是人。

## 复述和推导

### 控制流叙述

**泄漏：** "先规范化标签，然后截断它，然后包装它。"

**修正：**（删除。）

注释下面三行代码说的是同一件事。

### 测试讲解

**泄漏：** "这个测试创建一个会话，发送两条消息，等待第二条回复，然后断言日志有四条记录。"

**修正：** "两次往返必须正好产生四条日志记录：投影会对共享前缀去重。"

只保留非显然的断言理由；讲解只是复述测试本身。

## 含糊和计划残留

### 没有标记的推迟

**泄漏：** "暂时直接立即渲染应该没问题。"

**修正：**（删除；这项推迟已经有 `TODO(widget-batch):` 标记。）

没有归属的含糊说法是计划残留。如果没有标记，就写一个（`TODO(name): 按动画帧合并`），而不是保留这句话。

### 含糊的容量

**泄漏：** "64 KiB 的缓冲区对大多数情况应该够用了。"

**修正：** "64 KiB 能容纳观察到的最大帧（48 KiB）并留有余量；更大的帧会在 `decode` 中明确报错。"

用实际的上限和超出时的失败行为替换含糊的说法。

## 写作语言混杂

**泄漏：** `// renderer 跑在 client 端；spacing 看设计稿 ---- 私有 ----`

**修正：** `// The renderer runs on the client; spacing follows the design frame widget-badges.`

在一种语言的文字中夹带另一种语言的工作片段、会话分隔符，都是转录残留。设计稿画板的名称保留：它是按设计就在仓库外解析的外部来源。

## 保留

### issue 引用在任何地方都长期有效

**保留：** "上限作用于完整的渲染值，包括包装层（issue #1470 负责后续工作）。"

issue 在 HEAD 上从任何地方都能解析，"#N 负责后续工作" 正是 README 中放置推迟工作的合适方式。

### 失效的名称提及不算 "点出归属"

**删除：** "基于部件接缝的徽标渲染器（见部件渲染 RFC）。"

检验标准是可解析性，不是形式：没有任何已提交的文件叫 "部件渲染 RFC"，所以这个指针是失效的。如果存在已提交的归属，改指向它；否则删除。

### 抑制规则的理由

**保留（修正后）：** `// oxlint-disable-next-line no-non-null-assertion -- the one-element literal guarantees index 0.`

理由子句是必须写的文字。写的理由不对时（例如写着 "上面的循环保证了存在一帧"，附近却没有循环），改正理由，绝不删除。

### 实测的上限

**保留：** "深度上限（实测：512 层嵌套约 0.15 秒同步完成；4096 层会阻塞事件循环）。"

实测数据防止有人不明就里地调整这个常量，"实测" 表明这是数据而不是猜测。

### 运行时的新旧不是变更历史

**保留：** "旧连接排空后新连接才开始接受请求。"

这里的 "旧" 和 "新" 指交接过程中的两个运行时对象，不是仓库状态。禁止变更叙述针对的是仓库历史，不是生命周期用语。

### 运行时的自然时间不是版本戳

**保留：** "今天是几号？"

这个 prompt 问的是运行时时钟；"今天" 并不对比仓库状态。因为这段文字会到达模型，任何改写仍然需要对应的行为验证。

## 过度修正陷阱

精简一段文字之前，先列出它的命题。

### 把义务变成认可

**原文：** "这些直接注册是例外，等待迁移到插槽。"

**过度修正：** "这些直接注册是被认可的例外。"

**正确：** "这些直接注册是例外，等待迁移到插槽。"

"等待迁移" 是一项义务；"被认可" 是在为现状背书。这次精简在缩短句子的同时颠倒了它的情态。

### 把假设提升成已发布的功能

**原文：** "将来基于 IPC 的 shell 会继承执行器并重写 `spawn`。"

**过度修正：** "基于 IPC 的 shell 继承执行器并重写 `spawn`。"

**正确：** "一个假设的、基于 IPC 的 shell（目前不存在）会继承执行器并重写 `spawn`。"

只删掉 "将来" 会把一个设计示例变成 "这个类已经发布" 的声明。明确标出这是假设，而不是只删掉表示将来的词。

### 连同转录一起删掉了真实的事实

**原文：** "这段提示叙述了检查顺序；类型检查也是针对这段提示文字编译的。"

**过度修正：** （整句当作叙述删除。）

**正确：** "类型检查是针对这段提示文字编译的。"

半句是叙述，另一半是承重的耦合关系。命题共用一行时，删的是子句，不是整句。

### 保留了数字却丢掉了测量来源

**原文：** "4 MiB 的上限是实测得出的：生成的最大模块为 3.1 MiB。"

**过度修正：** "上限是 4 MiB；生成的最大模块为 3.1 MiB。"

**正确：** 保留 "实测"。

没有 "实测"，3.1 MiB 读起来像一个定义而不是一次观察，之后也没人会在提高上限前重新测量。
