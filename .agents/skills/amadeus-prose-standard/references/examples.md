# 提炼的文字例子

用这些例子识别适用的原则，不要当作套用的模板。"适中" 指在这个位置用最少的解释保留每一个承重的命题。

## 保留每个事实性子句

**原文：** "协调器会仔细地按会话串行化写入，在销毁完成前刷出缓冲的事件，并把后端失败报告给调用方。"

**删过头：** "协调器串行化持久化。"

**适中：** "协调器按会话串行化写入，在销毁完成前刷出缓冲的事件，并把后端失败报告给调用方。"

删的是装饰和重复，不是命题。行为主体、按会话的范围、销毁顺序和失败可见性是四个独立的事实。

## 明确的 skill 范围限制是有作用的

**删过头：** "读源码，自行判断。"

**适中：** "本 skill 是指导，不是完整的清单。在列出的检查之外也要自行判断；文档中的要求仍然适用。"

**写过头：** 用好几段论证为什么清单不能代替独立思考。

保留这条限制，因为它改变了 agent 执行工作流的方式。删掉的是重复的说服，不是护栏。

## 操作指南保留操作和验证

**删过头：** "给这个工具加测试。"

**适中：** "在单元层测试注册和销毁，通过真实的 Loader 组合运行这个工具，并确认断言观察的是外部结果，而不是模型的自述。"

**写过头：** 逐个讲解示例代码里已经能看到的每个 fixture 文件和断言。

保留测试层次、必须执行的操作、真实入口和可观察的验证。删掉 fixture 的叙述。

## 保留所有权和时机

**删过头：** "拆除时会取消提供方的工作。"

**适中：** "运行时先请求提供方取消，再释放子作用域；在销毁完成前汇合其 worker 的责任仍属于提供方。"

**写过头：** 按时间顺序讲述实现拆除用到的每个 promise 和回调。

行为主体、顺序、所有权转移的位置和完成保证是独立的事实性子句。

## 说明复杂代码，但不叙述它

**删过头：** "Worker 支持。"

**适中：** "拥有 worker 及其与宿主之间的桥接。初始化只执行一次；销毁会终止 worker，之后的调用会被拒绝。协议的理由见拥有它的文档。"

**写过头：** 逐段预告下面的类和辅助函数。

保留模块的角色、依赖、职责和非显然的生命周期行为。架构理由放链接，局部控制流让代码自己展示。

## 公共 JSDoc 写出失败

**删过头：** "返回 realm 的全局对象。"

**适中：** "返回已初始化的 realm 全局对象。初始化尚未完成或 realm 已被销毁时抛出。"

**写过头：** 导致每次抛出的内部状态机分支和具体的辅助函数调用。

抛出条件和状态前置条件是调用方可见的契约事实。

## 保留简洁的实现映射

**删过头：** "基于外部 API 的搜索提供方。"

**适中：** "把每条提供方结果映射为共享的搜索结果字段，保留标题、URL 和正文，丢弃提供方专有的排序元数据。"

**写过头：** 逐字段复述映射代码，包括同名字段和显而易见的赋值。

保留能说明适配层在哪里丢弃或改变了信息的映射细节。

## 链接理由，同时保留局部契约

**删过头：** "销毁行为见生命周期文档。"

**适中：** "销毁会中止运行并等待提供方静止。所有权和竞态处理见生命周期文档。"

**写过头：** 在每个销毁函数旁边重复生命周期文档里的 promise 编排和被放弃的所有权模型。

调用方需要的行为和完成保证留在使用处。算法和理由积极链接；链接不能代替局部契约。

## 安全边界可能需要一个具体例子

**删过头：** "挂载的插件拥有与宿主相同的权限。"

**适中：** "挂载的插件拥有与宿主相同的权限；例如，能访问 `ctx.shell` 就能以宿主执行器的权限运行命令。"

**写过头：** 列出插件可能滥用的每个服务和每种假想的攻击。

当一个例子能让抽象的安全限制在操作层面变清楚时，保留一个。

## 整段删除推理过程

**写过头：** "循环先检查值是否缺失。缺失时下一个分支提前返回，否则继续，所以最后的断言是安全的。"

**适中：** 代码已经表达了这些分支时，不写注释。如果提前返回保护的是一个非显然的不变量，只写出那个不变量。

不要把推理过程压缩成更短的叙述，而是删掉它。

## 配置注释解释配置本身看不出来的东西

**写过头：** "这一行加载本地文件系统提供方，接着是策略插件，接着是读、写、编辑工具。"（相邻的条目已经展示了这个顺序。）

**适中：** "策略插件要在面向模型的工具之前加载，这样写入和编辑调用才会经过先读后改的检查。"

保留顺序带来的后果、出人意料的范围规则或安全边界。条目清单让配置自己展示。

## 不要只为字数而删

**现状：** "适配层把提供方错误转换为共享的错误类型，让调用方可以统一处理认证、限流和临时性失败。"

**更短但更差：** "适配层统一提供方错误。"

**结论：** 除非附近的链接或契约已经列出了这些失败类别，否则保留现状。更短的版本丢掉了后果和区分，结构也没有变好。

## 模型可见的文字跟随归属

**删过头：** "调用失败时工具会返回错误。"

**写过头：** 把另一个包的 schema 和渲染文字复制进本包的 README。

**适中：** 引用本包拥有的稳定 prompt、结果和错误文字；其他包拥有的文字链接到那个包的 README，本地只写本包的条件或差异。

到达模型的措辞就是行为，但重复照样会走样。精确的原文放在归属处。

## 限制是契约，不是欠账清单

**删过头：** 省略一个进程生命周期内的缓存，而它导致修改配置后必须重载插件。

**写过头：** 列出私有辅助函数的清理和只给测试用的访问器，它们对调用方和维护者都没有影响。

**适中：** "提供方的选择在插件生命周期内缓存；安装或修复提供方后需要重载插件。" 普通的清理留在 TODO 里。

保留影响使用或安全维护的缺口和非显然约束。包 README 不是待办清单。
