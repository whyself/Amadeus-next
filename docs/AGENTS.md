# AGENTS.md：文档规范

本文件规定文档的分层、写作规则、字数预算和 slop 清单。写或审文字时的取舍判断用 [amadeus-prose-standard](../.agents/skills/amadeus-prose-standard/SKILL.md)，排查推理过程泄漏用 [amadeus-trim-cot-leakage](../.agents/skills/amadeus-trim-cot-leakage/SKILL.md)。

## 文档结构

文档的主题和它在目录树中的位置决定它的范围：只详细描述自己的主题，对直接下级只写用途、职责和高层行为，更细的内容链接到拥有它的下级文档。

文档写成参考：说明一个查阅范围内的当前行为，不安排学习顺序，不写教程。

## 分层：一事实一归属

每条事实只有一个归属，就是负责这类信息的那一层；其他地方放链接。

| 层 | 职责 | 不放在这里的内容 |
|---|---|---|
| 根 `AGENTS.md` | 每次会话都需要的常驻规则，每条一到三行，链接到规则的归属 | 故事、示例、特定情境的操作步骤、从链接处重复过来的内容 |
| 子目录 `AGENTS.md`（例如本文件） | 只在该目录成立的规则 | 根文件已有的全仓规则 |
| `docs/` 下的文档 | 跨包的说明：整体结构、插件之间的关系、面向用户的指南 | 单个包的细节（→ 包 README）、决策理由（→ Agent Notes） |
| [Agent Notes](../.agents/notes/README.md) | 有效的决策记录：为什么这样定、放弃了什么、必需的验证；`implemented/` 中的 Note 用现在时描述已落地的现实 | 决定落地后的迁移计划、验收任务清单、fixture 讲解和 "应该……" 式的规格用语 |
| 包 README（`packages/<name>/README.md`） | 单个包的使用契约：安装、配置、行为、失败方式、限制、对模型可见的影响；结尾章节见 [包 README](#包-readme) | 复述 JSDoc、其他包的事情 |
| JSDoc 与代码注释 | 调用方和维护者在使用处需要的契约 | 推理过程、变更经过、对评审者的辩护 |
| Skills（`.agents/skills/`） | 可复用的工作流和判断标准 | 产品和运行时契约（→ 文档或源码） |
| 提交信息 | 一次改动的原因、经过和验证 | 需要长期查阅的现行规则（→ 对应的文档层）、长期有效的决策理由（→ Agent Notes） |

放置：决策理由 → Agent Notes；包的契约 → README；常驻规则 → 根 `AGENTS.md`，附理由链接。

## 写作规则

- **写当前状态。** 历史放在提交信息和 Agent Notes 里。其他文字描述现在起作用的机制，不描述改动经过。
- **按 Agent Note 的创建标准判断是否写 Note。** 机械性和局部的改动不写，包括局部的 UI 调整；已有归属的 Note 要保持准确（[范围](../.agents/notes/README.md#什么时候写)）。
- **一段一行。** 每个段落只占一个物理行，换行交给编辑器的软折行，这样 diff 只显示真正改动的段落。代码块、表格和列表保留各自的格式。
- **注释和 JSDoc 写完整的契约，不写推理过程。** 保留行为、失败、时机、所有权、情态、例外、后果和非显然的方向信息；删掉叙述、测试讲解、评审分析和对代码的复述。在使用处保留局部契约，理由链接到它的归属。具体取舍见 [amadeus-prose-standard](../.agents/skills/amadeus-prose-standard/SKILL.md)。
- **直接命名。** 写出具体的检查、类型、API、操作或行为。"门禁"、"边界"、"形态"、"表面" 这类词用之前先检查能否换成更确切的名称；它正好命名确切的技术对象时保留（[规则](../.agents/skills/amadeus-prose-standard/SKILL.md)）。

## 包 README

每个包的 `README.md` 以下面两个章节结尾，顺序固定，由 `pnpm run doc-sync` 中的 `verify-package-readme-model-experience` 和 `verify-package-readme-limitations` 检查：

1. `## 模型体验`：本包放进模型请求的每一种内容（例如系统提示、工具定义、工具结果、插件会话记录）各写一个 `### <请求上下文与条件>` 小节，下面依次是 `#### 模型看到什么`（模型实际收到的字段；本包拥有的稳定 prompt 原文逐字引用）、`#### Token 影响`（固定、按条件、受上限约束或零直接影响）和 `#### KV Cache 影响`（只追加、前缀稳定、替换还是独立请求，以及哪些改动会让缓存失效）；某个字段没有影响时写 `无，因为……。`。整个包不向模型请求添加任何内容时，这一节只写一段 `无，因为……。`；只通过其他包影响模型时写 `间接，通过……。`。只写 "无" 不算说明。任何模型可见的变化都要在同一次改动中更新这一节。
2. `## 已知限制与延期工作`：使用方会碰到的缺口和维护陷阱，至少一条 `- ` 要点。确实没有限制的包登记进 `scripts/verify-package-readme-limitations.ts` 的 `NO_LIMITATIONS` 并写明理由，然后省略这一节。

## 字数预算

[scripts/doc-budgets.manifest.json](../scripts/doc-budgets.manifest.json) 为常驻文档设定上限；`pnpm run doc-sync` 中的 `verify-doc-budgets` 拒绝超出上限或已不存在的文件。计数时每个汉字算一个单位，其余按空白分隔的词各算一个单位。

门禁报错时按顺序处理：

1. **迁移**：属于其他层的内容移过去，需要时在原处留一行链接。
2. **精简**：属于这里但可以写得更短的内容，压缩它。
3. **提高上限**：只有内容确实需要更多空间时才提高，并在提交信息中说明理由。上限过低本身就是预算的缺陷。

上限是护栏，不是删减目标。低于目标时保留至少 5% 的余量；超过目标时冻结上限，直到迁移或精简让文档回到目标以下。只有文档仍有空间时才降低上限。目标（DSH 的英文词数上限乘以 1.7 后取整，1.7 是在 DSH 中英对照文档上实测的中文单位与英文词数之比）：根 `AGENTS.md` ≤ 3,500；本文件 ≤ 2,400；其他子目录 `AGENTS.md` ≤ 1,000。没有设预算的层由评审把关。

## Slop 清单

审查任何文档时逐项查找：

- **重复的规则**：搜索一句有辨识度的原文，只保留一处，其余改成链接。
- **写错位置的历史**：改写成现状描述，链接到历史的归属。
- **实现状态标注**：文字或图里的 "已实现！"、"未来：……"。状态会过期，由目录结构和包清单表达。
- **手抄的清单**：源码或生成器才是权威时，不手抄目录、JSDoc、测试清单或包清单。
- **推理过程转录**：逐步的实现叙述、对显然分支的论证、测试讲解、被放弃的局部方案。保留得出的契约或长期有效的理由，删掉推导过程。
- **在兄弟方法旁重复的理由**：只在拥有它的能力或辅助函数处写一次。
- **段落墙**：一个段落塞进好几条规则和括号旁注。拆开，或把细节移到它的归属。
- **强调泛滥**：到处加粗或"非常重要"等于没有重点。加粗只留给改变行为的那一句。
- **`implemented/` Agent Note 里的规格用语**："应该"、迁移计划、验收清单。已落地的 Agent Note 描述现状，见 [implemented 规则](../.agents/notes/implemented/AGENTS.md)。
